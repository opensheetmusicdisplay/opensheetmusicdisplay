Tab bend spans: original public comparison fixture

Source: tab_bend_spans.mscx, generated directly as a native MuseScore score
with nine GuitarBend spanners. It is an original test score, not an excerpt
from a private score. MuseScore 4.7.5 exported the matching
../test_tabs_bend_spans_musescore.musicxml. Importing that MusicXML back into
MuseScore can discard bends; open the native .mscx for the reference.

tab_bend_spans_musescore.png is the MuseScore reference render.
tab_bend_spans_osmd_before.png shows normal VexFlow bend layout.
tab_bend_spans_osmd_after.png shows the optional note-targeted bend layout.
The OSMD images use production bundles, a 1000px score container, SVG, and
NewSystemAtXMLNewSystemAttribute=true. The before build disables only the
endpoint assignment in VexFlowTabMeasure; both have the hidden-fret SVG
placeholder fix. Font, line style and spacing follow each renderer's defaults.

Cases, by measure:
1. Plain half-tone bend to an unparenthesized hidden endpoint.
2. Bend/release with parentheses on the hidden endpoint and visible final fret.
3. Bend/release without parentheses on the hidden endpoint. MuseScore adds
   parentheses to the final released fret automatically.
4. Quarter-note bend to a hidden half-note endpoint, followed by a rest.
5. Bend to a hidden endpoint with explicit parentheses, without a release.
6. Two separate bends, each with its own source and hidden endpoint.

Scope: adjacent single notes in the same measure and voice, on the same string
and fret, with pitches matching the bend interval. Parentheses alone do not
establish a continuation. Chords, grace notes, gaps, visible rearticulations,
nonmatching gestures and measure/system crossings keep normal VexFlow layout.
Playback is unchanged. More complex gestures can be handled separately.

Regression checks: TabBendSpans_Test.ts verifies note/label positions, release
ownership, black labels, setColor(), redraw/resize, conservative fallbacks and
SVG/canvas rendering. Existing tests also verify skyline/raster agreement.

Validation commands (after npm install):
  npm run prebuildVexflow
  npm run lint
  TEST_BROWSERS=chrome npm test
  npm run build:webpack

Based on upstream develop 7cf0e375. No app dependency or submodule pin is changed.
